search — 搜索

搜索并返回结构化 JSON。每条结果带稳定 id，可直接交给 fetch_page 深读该页，无需再手拼 URL。

请求示例

{
  "query": "2026年 大模型 最新进展",
  "maxResults": 10,
  "site": "github.com",
  "region": "us-en",
  "freshness": "week"
}

关键能力

  • 域名限定：site（单个）或 includeDomains / excludeDomains（数组），结果侧兜底过滤
  • 时间过滤：freshness=day|week|month|year 或精确 timeRange（优先级更高）
  • 区域提示：region 参与引擎自动选择与结果本地化
  • 中文查询自动改写：移除「20xx年」年份词 + 自动附加 freshness=year，通过 queryRewritten / queryYear 透明返回

响应结构

{
  "query": "2026年 大模型 最新进展",
  "queryRewritten": "大模型 最新进展",
  "engine": "bing",
  "engineSwitched": false,
  "cached": false,
  "total": 10,
  "deduped": 2,
  "freshnessApplied": true,
  "results": [
    { "id": "a1b2c3d4", "title": "...", "url": "https://...", "snippet": "...", "domain": "example.com" }
  ]
}

完整参数表见 API 参考 — 工具参数。

research — 一次调用完成整轮调研

替代 Agent「搜索 → 选页 → 抓取 → 总结」的循环，一次调用搞定。

{
  "query": "2026 LLM open source models comparison",
  "maxResults": 5,
  "fetchTopN": 2,
  "freshness": "month"
}

设计要点

  • 多页面并行抓取：单页失败记作 { url, error }，不影响整体结果
  • 智能选页：按域名多样性选取（先每个域名取排名最高的一条，再按排名补足），避免单站垄断；rank 字段标注原始排名
  • extractMode（默认 summary）：返回去噪正文要点省 token；full 返回整页 Markdown
  • 零 LLM 依赖：总结由宿主模型完成，MCP 内部不依赖任何 LLM，厂商无关

返回证据简报（evidence brief）

{
  "query": "...",
  "engine": "bing",
  "overview": { "total": 5, "results": [ { "id": "...", "title": "...", "url": "...", "domain": "..." } ] },
  "pages": [
    { "id": "...", "url": "...", "title": "...", "rank": 1,
      "headings": [ { "level": 1, "text": "..." } ],
      "content": "...", "length": 4000, "truncated": false }
  ],
  "note": "证据简报已就绪，请基于页面内容总结并标注来源 URL。"
}

fetch_page — 抓取网页转结构化内容

任意 URL（或搜索结果 id）转成可读内容。返回的 headings 是页面标题大纲 —— Agent 可先看结构再决定是否深读，省 token。

{
  "url": "https://example.com/article",
  "extractMode": "summary",
  "maxLength": 8000
}

也可以用搜索结果 id（免拼 URL）：{ "id": "a1b2c3d4", "maxLength": 8000 }。

extractMode 说明

模式返回字段适用场景
summary（默认）headings + 去噪正文 mainText（优先 <article> / <main> 容器）省 token，快速判断页面相关性
fullheadings + 整页 markdown需要完整上下文深度阅读
部分站点会拒绝脚本抓取（HTTP 403）（如百度百科、部分国内门户）：fetch_page 返回结构化错误，research 将对应页标记为失败并继续。

status — 透明状态页（诊断）

只读诊断工具。搜索失败时用 status 看为什么 —— 是全部引擎挂掉、某个引擎被限频，还是你自己的 IP 被临时 Ban。

{
  "method": "tools/call",
  "params": { "name": "status", "arguments": {} }
}

字段解读

  • 引擎状态机：untested（未用过）→ healthy / degraded（连续失败）→ cooling（冷却中，链会跳过）
  • cooldownUntil：冷却引擎的恢复时间戳，一眼看到何时恢复
  • cache：缓存命中统计 { size, hits, misses }
{
  "server": "ai-search-mcp",
  "uptimeSec": 1234,
  "config": { "engine": "auto", "region": "cn-zh", "ratePerMinute": 8, "cacheTtlMs": 600000 },
  "cache": { "size": 12, "hits": 34, "misses": 5 },
  "engines": [
    { "engine": "bing", "status": "cooling", "lastCode": "RATE_LIMITED",
      "consecutiveFailures": 3, "cooldownUntil": "2026-08-26T05:06:00.000Z" },
    { "engine": "baidu", "status": "healthy", "lastCode": null, "consecutiveFailures": 0 }
  ]
}
