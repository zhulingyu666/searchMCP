环境变量一览

默认零配置即可用；以下变量按需调整。完整数据表见 API 参考，这里按用途分组说明。

引擎与区域

变量默认说明
SEARCH_ENGINEauto单个引擎或逗号分隔引擎链（如 brave,tavily）；auto = 按区域自动选择
SEARCH_REGION—默认区域（如 cn-zh），参与引擎自动选择，同时是 search 的默认 region
SEARCH_LANG_ROUTING01 = 中文查询优先百度 / 搜狗（需对应网络可达）
SEARCH_MAX_RESULTS10默认结果条数（1–20）

缓存

变量默认说明
SEARCH_CACHE_TTL600缓存 TTL（秒，0 关闭）
SEARCH_CACHE_FILE—缓存持久化文件路径（如 ./.cache/search.json），重启不丢缓存（仅限单进程）

限频与超时

变量默认说明
SEARCH_RATE_PER_MINUTE8每个引擎每分钟最大请求数（0 关闭限频）
SEARCH_MIN_DELAY_MS / SEARCH_MAX_DELAY_MS500 / 2000请求间随机延迟范围（毫秒，0 关闭）
SEARCH_TIMEOUT_MS10000单次请求超时（毫秒）
FETCH_MAX_LENGTH8000fetch_page / research 单页 Markdown 长度上限（字符）

日志与隐私

变量默认说明
SEARCH_LOG_LEVELinfodebug|info|warn|error|off（结构化日志输出到 stderr，不污染 MCP 协议）
SEARCH_LOG_QUERY10 = 日志中打码查询词（隐私）

付费引擎与代理

变量默认说明
BRAVE_API_KEY—使用 brave 引擎必需
TAVILY_API_KEY—使用 tavily 引擎必需
SEARCH_HTTP_PROXY—代理地址（回退到 HTTPS_PROXY / HTTP_PROXY）
SEARCH_USER_AGENT内置自定义 User-Agent

常用配置场景

中国大陆免代理（默认推荐）

{
  "mcpServers": {
    "ai-search-mcp": {
      "command": "npx",
      "args": ["-y", "ai-search-mcp"],
      "env": { "SEARCH_REGION": "cn-zh" }
    }
  }
}

引擎链自动为 bing → so360 → baidu → sogou，全部国内直连，无需任何代理。

海外部署

不设 SEARCH_REGION（或非 cn 前缀）→ 默认链 google → bing → duckduckgo → yandex，Google 质量最优、Bing 最稳，任一失败自动转移。

付费引擎链（质量优先）

{
  "mcpServers": {
    "ai-search-mcp": {
      "command": "npx",
      "args": ["-y", "ai-search-mcp"],
      "env": {
        "SEARCH_ENGINE": "brave,tavily,bing",
        "BRAVE_API_KEY": "在此填你的Key",
        "TAVILY_API_KEY": "在此填你的Key"
      }
    }
  }
}

降低风控风险（被限频时）

SEARCH_RATE_PER_MINUTE=4 SEARCH_MIN_DELAY_MS=1000 SEARCH_MAX_DELAY_MS=3000 ai-search-mcp

网络注意事项

  • 免费引擎会限流：429 以结构化错误返回（RATE_LIMITED，带 suggestedEngine / retryAfter）；引擎链自动故障转移
  • 部分站点拒绝脚本抓取（HTTP 403，如百度百科）：fetch_page 返回结构化错误，research 标记该页失败并继续
  • 需要访问 DDG / Brave / Tavily 但处于墙内：SEARCH_ENGINE=duckduckgo SEARCH_HTTP_PROXY=http://127.0.0.1:7890 ai-search-mcp
  • 百度 / 搜狗对网络环境敏感：数据中心 / 海外 IP 下百度强制图形验证码（wappass）、搜狗被 302 拦回（antispider），会自动故障转移到 Bing / 360；大陆住宅 IP 可设 SEARCH_LANG_ROUTING=1 优先中文原生引擎

解析规则覆盖（免发版修复）

所有引擎的 SERP 解析规则外置在 src/selectors/*.json。某个搜索引擎改版导致解析失效时，不必等待新版 npm：

  1. 内置规则（随包分发，默认）
  2. 本地文件 SEARCH_SELECTOR_FILE=/path/selectors.json
  3. 远程 URL SEARCH_SELECTOR_OVERRIDE_URL=https://gist.../selectors.json（启动时拉取，优先级最高）
{
  "bing": {
    "challenge": ["captcha", "challenge"],
    "fields": {
      "title": {
        "pattern": "<h2[^>]*>\\s*<a[^>]+href=\"([^\"]+)\"[^>]*>([\\s\\S]*?)<\\/a>\\s*<\\/h2>",
        "flags": "gi",
        "urlGroup": 1,
        "textGroup": 2
      },
      "snippet": {
        "window": "after",
        "size": 2000,
        "pattern": "<p[^>]*>([\\s\\S]*?)<\\/p>",
        "flags": "i",
        "group": 1
      }
    }
  }
}
免发版工作流：用户报告「XX 引擎搜索坏了」→ 作者把修复后的规则更新到一个 Gist → 用户设 SEARCH_SELECTOR_OVERRIDE_URL=<gist> 重启即修复。覆盖加载失败（文件损坏 / 网络不通）永不阻塞启动，自动回退上一级规则并打 warn 日志。

合规说明

  • 只返回搜索摘要与链接，不转载全文；遵循目标站点 robots.txt 与服务条款
  • 内置礼貌爬虫限频（默认 8 次/分）+ 随机请求间隔，主动避免触发风控
  • 合规红线：不做验证码绕过、UA 伪造轮换、代理池轮换等反反爬对抗
  • 被 403 / 验证码拦截时，请降频或切换引擎
